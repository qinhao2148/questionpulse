# QuestionPulse 功能与状态逻辑审计

审计日期：2026-10-22

## 核心结论

QuestionPulse 课堂与保利威直播是两个相互关联但生命周期不同的系统。QuestionPulse 管理提问、聚类、讲解状态和报告；保利威负责采集、推流与播放。结束 QuestionPulse 课堂会立刻关闭学生端播放器并冻结课堂数据，但不会远程终止保利威推流。演示结束时仍需在保利威导播台点击停止直播。

## 已修复的用户流程

| 场景 | 期望行为 | 当前实现 |
| --- | --- | --- |
| 创建课堂 | 课题由教师输入 | 首页提供课题名称输入框，不再写死演示主题 |
| 学生进入进行中课堂 | 显示真实课题和直播状态 | 先显示课堂占位状态，播放器成功建立后切换到真实画面 |
| 播放失败或网络波动 | 不遮挡内容并可恢复 | 自动重试两次，之后提供“重新连接直播”按钮 |
| 保利威未开播 | 页面保持可理解状态 | 显示等待开播，不再把装饰雷达覆盖到播放器上 |
| 学生提问 | 仅进行中课堂可提交 | 课堂结束后输入框和提交按钮禁用，后端同时返回 409 |
| 教师结束课堂 | 冻结本堂课并生成报告 | 学生播放器立即销毁，教师端进入只读归档态 |
| 结束后继续访问 | 不再暴露直播内容 | 页面显示已结束状态，不加载保利威播放器，即使频道仍在推流 |
| 开始下一堂课 | 保留旧报告并可继续教学 | 教师端提供“创建下一堂课”，生成新的课堂 ID 并进入新课堂 |
| 结束后修改数据 | 所有写操作均应拒绝 | 聚类状态、反馈、移出聚类、重试同步和测试导入均由后端拒绝 |
| 教师统计 | 学生人数不重复计算 | 按提问者 ID 去重，不再按每个聚类人数累加 |

## 页面与数据状态

课堂状态只有 `live` 和 `ended`。`ended` 是不可逆的归档状态；再次授课会创建新课堂，避免旧报告、旧问题和新直播混在一起。

播放器状态分为 `idle`、`loading`、`ready`、`playing`、`waiting`、`degraded` 和 `ended`。播放器通过保利威频道状态和播放事件更新显示。课堂结束时会停止并销毁播放器实例，清空播放器容器。

前端限制用于正确呈现和减少误操作，后端 409 校验才是数据一致性的最终保障。

## 已验证范围

- Vue TypeScript 类型检查与 Vite 生产构建。
- FastAPI 路由、数据库迁移检查和完整自动化测试。
- 自动化测试覆盖结束课堂后的提问、聚类状态、反馈、移出聚类和重试同步拒绝逻辑。
- 自动化测试覆盖结束后创建独立新课堂。
- 学生端和教师端结束态已做页面复核，播放器与雷达装饰不会继续显示。
- 路由采用按页面加载，非学生页面不再提前加载保利威播放 SDK。
