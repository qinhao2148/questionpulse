# 5—12 小时开发成果：讲解、反馈与报告闭环

完成日期：2026-10-20。此阶段全部使用本地 QuestionPulse 数据，没有调用或修改 POLYV。

## 状态机

```text
open → addressing → awaiting_feedback → closed
  ↑          ↑              │             │
  └──────────┴──────────────┴─────────────┘
                 重新打开
```

- 每次修改携带 `expected_version`，旧版本请求返回 409，避免教师多窗口互相覆盖。
- 从 `addressing` 进入 `awaiting_feedback` 时，反馈轮次加一，并冻结当时疑问簇内的独立学生集合。
- 关闭表示教师结束处理，不等于全体学生理解；重新打开保留已有反馈历史。

## 反馈约束

- 只有当前轮目标学生能够反馈。
- 每人每轮只有一条有效记录；再次提交会覆盖结果，不增加反馈人数。
- 反馈结果仅为 `understood` 或 `still_confused`。
- 学生快照只包含自己的原始问题；教师快照和报告保留完整可追溯原文。

## 事实报告

`GET /api/v1/sessions/{id}/report` 直接从数据库计算：

- 问题数、独立提问人数、疑问簇数和各处理状态数量。
- 当前反馈轮目标数、响应数、覆盖率、已理解与仍困惑人数。
- 高频疑问排序、原始问题清单和仍困惑跟进清单。

报告数字不由 LLM 生成。浏览器报告页支持刷新、展开原始问题和打印。

## 验证证据

- 自动化测试覆盖合法状态流转、非法版本冲突、目标冻结、反馈覆盖更新、关闭、重新打开和报告统计。
- MySQL 8.0.41 已迁移到 `20261020_0003 (head)`。
- 浏览器端到端验证：学生提交问题 → 教师开始/结束讲解 → 学生反馈仍困惑 → 教师统计更新 → 报告出现跟进项 → 关闭并重新打开。
- 实测样例：7 条问题、7 名独立提问者、3 个疑问簇、反馈 1/4、覆盖率 25%、仍困惑 1。
