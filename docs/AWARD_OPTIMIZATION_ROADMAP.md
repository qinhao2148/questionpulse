# QuestionPulse 获奖导向优化路线

更新日期：2026-10-22

## 决策原则

比赛评分维度为创新力、技术实现力、体验与设计力、实际价值、展示与感染力。功能优先级按照“是否同时提升多个维度”和“是否能在三分钟内被评委看懂”排序。

保利威已有基础提问、问答、知识库答疑、AI 数字人和回放 AI 摘要/测验。QuestionPulse 不与这些能力正面重复，重点解决直播进行中教师无法快速识别群体困惑、验证讲解效果的问题。

| --- | --- | --- | --- |

| P0 | DeepSeek 主要语义聚类与可解释决策 | 创新、技术实现 | 中 |

## P0-1 教师悬浮助手

将 QuestionPulse 作为浏览器扩展注入 POLYV 网页开播台。教师不切换页面即可查看 Top 疑问、独立学生人数、理解反馈和 AI 建议。

验收重点：

- 不遮挡摄像头、麦克风、开始直播和结束直播。
- 新高频疑问出现时给出一次轻提示，不持续干扰。
- 可收起、拖动并记住位置。
- API 断开时明确降级，不影响 POLYV 开播。

## P0-2 DeepSeek 主要语义聚类

DeepSeek 负责问题意图、聚类、标题和理由；MySQL 负责人数、反馈率、状态和审计。保留本地语义哈希为降级方案。

必须展示的技术证据：

- 结构化 JSON Schema。
- 模型返回 ID 的服务端校验。
- `ai_runs` 和 `ai_decisions` 审计记录。
- DeepSeek 超时、限流和非法输出的降级路径。
- 与本地算法在固定标注集上的指标对比。

## P0-3 课堂即时检测题

这是最值得增加的新闭环。教师讲解完一个疑问簇后，DeepSeek 根据原始问题和教师确认的知识点生成一道选择题，教师预览并确认后发送给受影响学生。

流程：

```text
群体疑问 → 教师讲解 → AI 生成检测题 → 教师确认
        → 学生作答 → 数据库评分 → 判断是否真正理解
```

相比单纯的“已理解/仍困惑”，客观题可以减少学生自我感觉偏差。报告同时展示：

- 主观反馈理解率；
- 即时检测正确率；
- 两者差异；
- 需要再次讲解的知识点。

数据表建议：

- `check_questions`
- `check_options`
- `check_targets`
- `check_responses`

AI 只生成题目草稿和标准答案；教师确认后才能发送，作答统计由数据库完成。

## P0-4 群体困惑预警

建立可解释的 `confusion_score`，让“疑问脉搏”成为可计算的产品能力，而非装饰动画。

建议公式：

```text
困惑分 = 独立提问人数权重
       + 最近一分钟问题增长率
       + 等待处理时长
       + 讲解后仍困惑比例
       + 即时检测错误率
```

每一项先归一化到 0～1，权重写入配置并在报告中可解释。DeepSeek负责生成一句提醒文本，不负责计算分数。

三个等级：

- 绿色：无需打断授课。
- 黄色：建议教师关注。
- 红色：多人集中困惑，建议暂停讲解。

## P1-1 AI 评测面板

使用现有标注集对比：

- 本地语义哈希；
- DeepSeek；
- DeepSeek 失败后的 fallback。

展示指标：pairwise precision、recall、F1、ARI、平均延迟、失败率和单批成本。评委可以看到选择 DeepSeek 有量化依据，而不是只靠主观演示。

## P1-2 疑问时间线

将课堂问题按时间绘制为脉搏时间线：

- 哪个时间点问题突然增加；
- 当时主要困惑是什么；
- 教师何时开始讲解；
- 讲解后主观反馈和检测正确率如何变化。

若后续能获得回放时间映射，再将时间线与回放跳转关联。第一版只做本地课堂时间线，不依赖回放 API。

## P1-3 演示导演模式

为比赛增加一条不影响真实功能的演示辅助流程：

- 创建全新课堂。
- 显示下一步演示提示。
- 一键加载明确标注的合成学生问题。
- 在真实 POLYV 不稳定时切换为本地降级。
- 自动检查三端地址、数据库和 AI Provider 状态。
- 演示结束后生成结果摘要和证据截图清单。

演示模式必须明确标注合成数据，不伪装成真实观众。

## P2 功能

### 学生复习卡

根据学生本人提出的问题、反馈和即时检测结果生成课后复习卡。只使用该学生可见的数据，不暴露其他学生原文。

### 多课堂趋势

按课题和知识点比较多堂课中的高频疑问、检测正确率和重复出现的问题。该能力适合展示产品未来商业价值，但需要身份体系、权限和更多真实数据，比赛阶段不应优先。

## 不建议投入的方向

- 通用聊天机器人：与保利威知识库答疑和 AI 数字人重叠。
- 自动替教师回答全部问题：削弱本项目“帮助教师理解群体状态”的定位。
- 复杂数字人形象：展示成本高，教学价值弱，且保利威已有数字人助手。
- 知识图谱和完整 RAG：短期难以证明数据质量。
- 多 Agent 编排：增加不可控性，评委难在三分钟内理解价值。
- 语音转写：保利威已有实时字幕和回放逐字稿能力，重复建设价值有限。
- 原生移动 App：不会加强核心闭环。

## 推荐实施顺序

1. 悬浮助手基础版。
2. DeepSeek 聚类及审计记录。
3. 即时检测题完整闭环。
4. 困惑分和主动提醒。
5. AI 与本地算法评测面板。
6. 疑问时间线。
7. 演示导演模式与最终视觉打磨。

## 功能冻结条件

出现任一情况时停止增加功能，只修复和演练：

- Edge 中悬浮助手或真实直播仍不稳定。
- DeepSeek 失败时会丢问题或阻断课堂。
- 即时检测题不能由教师审核后发送。
- 课堂结束后仍能写入数据。
- 三分钟演示无法稳定完成两遍。
- 提交包出现密钥、令牌或真实学生身份。

获奖重点不是功能数量，而是清晰展示一条可信闭环：发现群体困惑、解释 AI 判断、辅助教师讲解、客观验证理解、课后持续改进。
