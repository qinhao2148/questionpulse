## 1. 一句话定位

QuestionPulse 是运行在 POLYV 直播课堂旁边的“群体疑问雷达”：接收学生问题，将不同表述的同类困惑聚合成疑问簇，按受影响学生人数帮助教师排序处理，并用讲解后的学生反馈验证问题是否真正解决。

它不替代 POLYV 的直播、提问或问答功能。POLYV 提供直播与官方互动数据，QuestionPulse 增加聚类、教学处理、理解反馈和课后追踪。

## 2. 比赛价值

核心应用场景是直播课堂中问题数量多、表达分散、重复问题难以统计。产品闭环为：

```text
POLYV 直播/提问
      ↓
QuestionPulse 幂等入库
      ↓
相似问题聚类并统计独立学生
      ↓
教师按影响范围讲解
      ↓
受影响学生反馈“已理解/仍困惑”
      ↓
生成可追溯课后报告
```

参赛创新点应表述为“在 POLYV 互动能力上增加群体疑问识别与教学闭环”，不能表述为“保利威完全没有类似功能”或“用 AI 自动替代教师”。

## 4. 四个页面

| 页面 | 路径 | 作用 |
| --- | --- | --- |
| 创建页 | `/` | 输入课堂课题并创建独立课堂 |
| 学生端 | `/student/:sessionId` | 观看 POLYV 直播、提交疑问、查看讲解状态并反馈 |
| 教师端 | `/teacher/:sessionId` | 查看疑问簇、同步 POLYV、处理问题、纠错和结束课堂 |
| 报告端 | `/report/:sessionId` | 查看课堂事实统计、未闭环问题、打印和导出 CSV |

学生端每 3 秒读取一次课堂快照。当前版本没有实现 QuestionPulse 自有 WebSocket；POLYV SDK 的实时连接只负责保利威直播与互动。比赛规模下轮询足够稳定，也更容易恢复。

## 5. 两套状态机

### 课堂状态

```text
live → ended
```

`ended` 是不可逆归档状态。归档后学生端销毁播放器，所有业务写接口返回 409。继续授课会创建新课堂，旧提问和报告不会混入新课堂。

### 疑问簇状态

```text
open → addressing → awaiting_feedback → closed
  ↑          │               │             │
  └──────────┴───────────────┴─────────────┘
```

教师可以重新处理疑问簇。进入 `awaiting_feedback` 时冻结本轮需要反馈的学生集合，因此反馈覆盖率的分母可追溯。

## 6. 技术架构

| 层 | 当前实现 |
| --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Vue Router |
| 直播与互动 | `@polyv/live-watch-sdk`、`@polyv/interactions-receive-sdk` |
| 后端 | Python 3.11、FastAPI、Pydantic、SQLAlchemy Async |
| 数据库 | MySQL 8、utf8mb4、Alembic |
| 聚类 | 256 维中文字符 n-gram 语义哈希向量与余弦相似度 |
| 数据同步 | FastAPI REST；学生端 3 秒轮询课堂快照 |
| 本地运行 | Docker Compose 仅运行 MySQL；前后端作为本机进程运行 |

当前聚类模型是可离线复现的轻量算法，不调用外部大模型，也不是训练好的中文 Embedding 模型。它保证比赛现场无网络时仍可演示。V2 将接入 DeepSeek 作为主要语义分析层，当前算法保留为 API 异常时的降级方案。

## 7. POLYV 集成边界

已验证的真实链路：

1. 学生端通过官方观看页 SDK 连接频道并观看直播。
2. 学生可以通过 SDK 向 POLYV 发送提问。
3. FastAPI 使用保存在服务端的 App ID/App Secret 生成签名并读取官方记录。
4. 官方问题映射为统一问题模型，并按 `session_id + source + external_id` 去重。
5. 同一条记录再次同步不会增加问题数。

QuestionPulse 的“结束课堂记录”不会结束保利威推流。比赛演示结束时必须另外在保利威主播控制台结束直播。

App Secret、推流密钥和主播令牌只能保存在本机忽略文件中，不能进入前端、源码包、海报、录屏或日志。

## 8. 数据模型

主要表包括：

- `sessions`：课堂课题、课堂状态、POLYV 频道和接入状态。
- `participants`：课堂内的匿名参与者。
- `questions`：原始问题、来源、官方 ID、向量和处理状态。
- `submissions`：客户端请求幂等记录。
- `clusters`：疑问簇、向量质心、状态、版本和反馈轮次。
- `cluster_events`：状态变化和人工纠错审计记录。
- `feedback_targets`：每轮反馈应答学生集合。
- `feedback`：学生每轮最后一次有效反馈。

## 10. 当前风险

1. **Edge 播放兼容性**：必须用真实 Edge 和真实推流复核，重点检查自动播放、第三方 Cookie、扩展和控制台错误。
2. **无应用身份认证**：课堂 UUID 即访问入口，不能作为公开生产系统部署。
3. **轮询而非实时推送**：状态最长约 3 秒后更新；比赛演示可以接受。
4. **聚类是轻量算法**：对未覆盖领域的同义表达可能误分，需要教师人工拆分兜底。
5. **学生端 SDK 包较大**：生产构建约 1.12 MB；已按页面拆分，不影响教师端和报告端首屏。
6. **保利威与本地课堂生命周期独立**：结束课堂后还要单独停止推流，演示操作顺序必须固定。

## 11. 推荐比赛演示顺序

1. 在保利威主播端开播，确认学生端出现真实画面。
2. 展示两个学生用不同说法提出同一困惑。
3. 教师端同步 POLYV 问答，展示官方来源 ID 和去重。
4. 展示两个问题归入同一疑问簇及独立学生人数。
5. 教师开始讲解、结束讲解，学生提交理解反馈。
6. 展示教师看到仍困惑人数，并人工拆分一条误聚类问题。
7. 结束 QuestionPulse 课堂，证明学生端立即关闭播放器且数据只读。
8. 展示课后报告，然后在保利威主播端结束直播。
9. 若时间允许，点击“创建下一堂课”，证明旧报告保留、新课堂从零开始。

## 13. 已确定的 V2 方向

- 使用 Chromium Manifest V3 扩展，将 QuestionPulse 悬浮助手注入 POLYV 网页开播台。
- 教师无需切换页面即可看到疑问 Top 3、理解反馈和操作建议。
- DeepSeek 负责问题意图理解、主要聚类、标题、摘要和教学建议。
- MySQL 继续负责官方 ID 去重、人数、反馈率、状态和审计等事实数据。
- 所有 AI 写操作必须经过服务端校验；改变课堂状态的操作必须由教师确认。
- 当前本地语义哈希算法作为断网、超时、限流时的降级能力。

实施与验收标准见 [V2_TEACHER_COPILOT.md](./V2_TEACHER_COPILOT.md)。
