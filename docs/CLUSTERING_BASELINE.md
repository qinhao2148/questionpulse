# 离线聚类基线评测

本基线用于证明评测链路、暴露简单文本匹配的上限，并为中文语义向量方案提供对照。它不是比赛最终模型。

## 数据与复现

- 数据集：`fixtures/classroom_questions.jsonl`
- 76 条课堂消息，其中 72 条问题、4 条非问题；12 个标准疑问簇。
- 46 条训练数据用于选择阈值，26 条留出数据只用于最终评测。
- 每条记录含稳定 ID、匿名参与者、标准簇、train/eval 划分和问题标记。

```powershell
cd backend
uv run python scripts/evaluate_clustering.py ../fixtures/classroom_questions.jsonl --output ../docs/clustering-baseline.json
```

机器可读结果见 `docs/clustering-baseline.json`。该文件由脚本生成，不手工修改。

## 方法与结论

对中文文本做字符 2—4 gram TF-IDF，再按到已有簇成员的最大余弦相似度执行在线聚类；阈值只在训练集搜索。最终报告中的精确数值以 JSON 为准。

| 数据划分 | 最佳阈值 | Pairwise Precision | Recall | F1 | ARI |
|---|---:|---:|---:|---:|---:|
| 训练集（选择阈值） | 0.15 | 0.3333 | 0.0152 | 0.0290 | 0.0236 |
| 留出评测集 | 0.15 | 0.0000 | 0.0000 | 0.0000 | 0.0000 |

评测集 26 个问题被拆成 26 个簇，说明这个纯字面基线完全无法泛化到刻意改写的同义提问。这里保留零分，而不是调低阈值直到评测集好看；阈值只能由训练集选择。

基线出现大量错误拆分：例如“递归为什么一定要有结束条件”和“没有 base case 程序是不是停不下来”共享概念却可能没有足够字面重合。它也会把都包含 Promise/递归的不同问题误合并。由此确定比赛实现路线：

1. 主模型使用固定版本的中文 embedding，并保留模型名与相似度。
2. 先做高置信自动归簇，中间置信度进入教师确认，低置信度新建簇。
3. UI 必须支持人工拆分，模型结果不能成为不可修改的事实。
4. TF-IDF 仅在 embedding 超时或不可用时降级，并在教师端标示来源。
5. 下一轮用同一留出集比较 pairwise precision、recall、F1 和 ARI，不能用演示观感替代评测。
