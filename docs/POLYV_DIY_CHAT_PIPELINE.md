# 保利威定制观看端与聊天疑问链路

## 目标

本项目不再依赖无法访问内部 SDK 实例的保利威现成观看页。学生入口跳转到本地部署的 `polyv-watch-client`，该目录来自保利威官方 `polyv-web-live-watch-sdk` v2.20.0，并只在上层增加 QuestionPulse 业务面板，不改写播放器和聊天室底层协议。

## 数据流

1. 学生直接打开本地定制观看端，用课堂码加入；后端签发仅限该课堂的学生令牌，并生成不暴露内部身份的 `polyv_viewer_id`。
2. 学生进入 `http://127.0.0.1:15021/index.html`，频道号、昵称通过查询参数传递；QuestionPulse 令牌先放在 URL fragment 中，页面加载后立即移入 `sessionStorage` 并清除 fragment。
3. 保利威聊天室确认公聊发送成功后，定制面板仅上报当前学生自己的文本消息、官方消息 ID、场次和时间。图片、红包、自定义消息、他人消息和发送失败消息不会上报。
4. FastAPI 以 `(session_id, source, external_id)` 幂等保存，DeepSeek 输出结构化 `is_question / confidence / question_type / reason`。没有模型或模型失败时使用保守的本地规则。
5. 高置信度课程疑问自动进入现有聚类；中等置信度进入教师审核；社交消息、设备/网络问题和低置信度消息保留审计记录但不进入疑问区。
6. 教师点击“同步聊天与提问”时，后端使用 `appId + appSecret` 签名调用聊天历史 API，只拉公开、已审核、文本类学生消息，对实时上报记录做官方确认，并补录遗漏消息。
7. 教师将疑问置为“讲解中”再“等待反馈”后，定制观看端出现“已理解/仍困惑”。教师可按反馈生成、审核并发布选择题，目标学生直接在观看端作答。

## 安全与边界

- `appSecret` 和 DeepSeek API Key 只允许存在于 FastAPI 环境变量中。
- 浏览器上报必须携带学生课堂令牌，participant 由令牌解析，不能由请求体任意指定。
- 服务端历史同步必须携带教师令牌；官方文档明确要求签名调用经客户服务端中转。
- 分类不在 HTTP 请求内执行：消息先以 `pending` 落库并立即返回，由响应后的后台任务调用模型并写入结论。进程在分类前退出时，教师下一次同步会把这些 `pending` 消息重新入队。生产规模建议换成持久任务队列，并批量调用模型、设置速率与费用上限。
- 教师端现阶段主动触发历史补偿，避免违反保利威接口限流；生产环境可按官方额度加入低频定时同步和退避。
- 聊天历史的时间窗从 `sessions.chat_synced_at`（首次为建课时间）减去 2 分钟重叠开始，避免每堂课都从头重放。
- 消息带有保利威 `sessionId` 时会与本课堂绑定的场次比对，不一致的直接跳过；课堂尚未绑定场次时，首次同步若只观测到一个场次则自动绑定。

## 运行与验收

```powershell
./scripts/bootstrap.ps1
./scripts/start-demo.ps1
./scripts/check.ps1
```

最小真人验收：两个学生分别发普通回应和课程疑问；确认普通回应不进入疑问区、疑问自动收录或出现在审核区；断开一个学生的 QuestionPulse 上报后发送疑问，再用教师端同步补录；完成讲解、理解反馈、发布检测题和作答；最后在报告页核对问题数、独立人数、反馈与答题结果。
