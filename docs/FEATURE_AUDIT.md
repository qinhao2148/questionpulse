### 4. 后端与集成

- 三层鉴权：教师后台令牌 `qpa_*`、课堂令牌 `qpt_*`、学生令牌 `qps_*`（可多设备并存）。
- 问题提交：幂等 `client_request_id`，DeepSeek 语义聚类 + 本地向量降级。
- 聊天疑问识别：消息以 `pending` 落库并立即返回，响应后由后台任务调用 DeepSeek 分类（`is_question / confidence / question_type / normalized_intent / suggested_question / reason`），不可用时退化本地规则；`pending` 消息会在下次同步时重新入队。
- POLYV 服务端补偿：签名调用聊天历史与 Q&A 接口，按 `chat_synced_at` 增量拉取、官方消息 ID 幂等去重、按场次过滤，`appSecret` 只在后端。
- 反馈：按轮次记录目标与结果，支持重新讲解后的第 N 轮。
- 理解检测：按「疑问簇 + 轮次」唯一，发布时下发给课堂内具名学生。
- 报告：问题、独立参与者、反馈覆盖、检测正确率、处理时间线、AI 建议。
- 观看心跳：学生端拉快照时每 30 秒记一次 `last_seen_at`，用于区分「加入了」和「真的在看」。

## 二、发现的问题与处理

### 已修复

| # | 问题 | 影响 | 处理 |

| 1 | 教师工作台不自动刷新，页面却写着「新问题会自动出现在下方」 | 教师必须手点刷新，课堂上容易漏掉新疑问 | 5 秒轮询；标签页隐藏或报告展开时暂停；课堂码输入期间不回填 |

### 第四轮修复（聊天同步后分类静默失败）

| # | 问题 | 处理 |
| --- | --- | --- |
| 25 | `chat/sync` 把分类任务交给 `BackgroundTasks` 时漏传 `db.bind`，后台任务抛 `TypeError: missing 1 required positional argument`，只写进服务端日志。接口仍返回 `accepted: N`，但每条消息永远停在 `pending`，教师端和悬浮窗看起来「什么都没抓到」 | 补传 `db.bind`（与 `/chat-messages` 路径一致）；新增回归测试 `test_chat_history_sync_classifies_into_a_cluster`，断言「同步 → 分类 → 进疑问簇」整条链，而不是只断言计数器 |
| 26 | 悬浮窗没有同步入口，只能回教师端点「同步聊天与提问」；新课堂在同步前必然是空的 | 面板底部新增「同步聊天」，显示拉取/新增/去重条数；某堂课从未同步过（`last_synced_at` 为空）时，首次打开自动拉一次，之后手动补，避免高频调用官方接口 |
| 27 | 首次同步时课堂还未绑定场次，写入的消息 `polyv_session_id` 为 `NULL` | 落库时回退用事件自身的 `polyv_session_id`，与随后绑定的场次保持一致 |
| 28 | 空面板只说「暂时没有课堂疑问」，不解释为什么学生在聊天框里的提问没出现 | 空态补一句提示：保利威聊天框的提问不会自动推送，需点「同步聊天」 |
| 29 | 聊天同步只有手动入口：只要老师不点按钮，新发的消息永远不会出现在教师端和悬浮窗，看起来就像「没记录」 | 教师端与悬浮窗都在轮询里加了 20 秒节流的自动拉取（仅课堂未结束、标签页可见时执行，失败静默），手动按钮保留用于立即拉取 |
| 30 | 悬浮窗的「首次打开自动同步」只在 `last_synced_at` 为空时生效，课堂同步过一次后就再也不自动拉 | 由第 29 条的周期自动同步覆盖；首次打开仍保留一次立即拉取，保证刚开课时不用等 20 秒 |

### 第五轮修复（提问到教师端可见的延迟）

后端本身不慢：教师快照 12 ms、`chat/sync` 283 ms（无新消息）、DeepSeek 单条分类平均 1780 ms（`ai_runs` 实测 8 条）。慢在轮询节奏与两处并行调用。

| # | 问题 | 处理 |
| --- | --- | --- |
| 31 | 自动同步 20 秒一次、快照 5 秒一次，学生在聊天框发言最坏要 25 秒才出现 | 自动同步降到 6 秒、快照轮询降到 3 秒。一次同步约 300 ms，6 秒节奏约 10 次/分钟，仍在官方接口可接受范围 |
| 32 | 同步与刷新同时发出（`void autoPullChat(); void refresh()`），本轮刷新必然在新消息落库前返回，等于每次同步白等一个完整轮询周期 | 改为先 `await` 同步、再刷新；加 `pollBusy` 防重入，避免一次同步超过间隔时请求堆积 |
| 33 | 分类在 HTTP 响应之后才开始，同步完立刻读快照时消息仍是 `pending`，簇还没形成 | 同步到新消息后 2.5 秒补读一次快照（模型均值 1.8 秒），不用等下一个完整周期 |
| 34 | 手动「同步聊天与提问」同样先刷新后分类，提示「新增 N 条」但列表为空 | 手动同步也走同样的补读，并把 `lastAutoSyncAt` 重置，避免紧接着的周期同步重复请求 |
| 35 | 悬浮窗存在同样的并行问题（`void autoSyncChat(); void refresh()`） | 同样改成先同步后刷新，并在拉取到新消息时补读一次 |

### 第六轮修复（同一浏览器多标签被当成同一个学生）

现象：同一台电脑开两个标签页，用不同名字、同一个课堂码加入，第二个页面加入后前一个页面失效；加入页的名字栏还自带一个使用者没输入过的旧名字。

| # | 问题 | 处理 |
| --- | --- | --- |
| 36 | 学生身份 `viewer_key` 存在 `localStorage`，同浏览器所有标签页共用同一个值。后端以 `(session_id, viewer_key)` 判定参与者，于是第二个标签页不是新学生，而是把第一个学生改名——`participant_id` 不变、`polyv_viewer_id` 不变，POLYV 侧仍是同一个观众 | 改为 `sessionStorage`：每个标签页独立身份，刷新页面仍然保留。新增 `tabViewerKey()` 并写明原因 |
| 37 | 同一参与者每次加入都签发新 token，只保留最近 5 个（`MAX_STUDENT_TOKENS`）。反复用不同名字加入时旧 token 被淘汰，先前打开的页面下一次轮询收到 `403 access_denied`，被 `leaveClassroom` 弹窗并跳回加入页——表现就是「只能保留一个页面」 | 第 36 条修好后每个标签是独立参与者、各自一个 token，不再互相淘汰。实测同一 viewer_key 连续加入 7 次时，第 3 次的 token 已被判 403，印证了淘汰行为 |
| 38 | 加入页的名字输入框用 `localStorage.questionpulse.display_name` 预填，使用者没输入也会带着上一个人的名字进入课堂（「欢迎小陈」的来源） | 不再预填，也不再往本地存名字；输入框为空时按钮保持禁用 |

### 第七轮修复（sessionStorage 也会被“复制标签页”带走）

现象：第 36 条改完后仍出现保利威错误页「浏览器重复打开了相同的标签页或当前账号已在其他地方登录」，页面停在 `*.live.polyv.cn/error?causeBy=ChatReloginMsg`，卡片上显示的名字（如「小龙虾」）不是任何一个学生输入过的名字。

| # | 问题 | 处理 |
| --- | --- | --- |
| 39 | `sessionStorage` 虽然按标签页隔离，但「复制标签页」和带 opener 的新开标签会连内容一起克隆；两个标签于是共用同一个 `viewer_key` → 同一个 `participant_id` → 同一个 `polyv_viewer_id`。POLYV 聊天只允许一个活跃会话，后登录的把先登录的踢到错误页（`ChatReloginMsg` / `OverLoginLimit`） | `viewer_key` 改为**只存在于内存**：每次进入加入页时 `mintViewerKey()` 现生成，不落任何 storage。加入之后标签页靠 token 认人，刷新不受影响 |
| 40 | 错误页上显示的「小龙虾」并不是脏数据：学生端代码从不往 localStorage / cookie 写昵称，SDK 也只缓存 `rtas_geo_cache`。这个名字是保利威给**没有昵称的匿名观众**随机分配的，出现它说明那个标签页根本没带 `viewerid` / `nickname` 在播放 | 加入表单页面本身不再播放身份不明的流：无凭证时统一领一个 `qp-guest-<uuid>` 的 viewer id，避免多个“游客”标签页共用一个身份互踢 |
| 41 | 复制已加入课堂的标签页时，URL 里还留着上一个学生的 `viewerid` 和 `nickname`，本页却没有对应 token，于是“用别人的身份播放” | 挂载播放器前 `stripStaleViewerIdentity()` 清掉遗留的 `viewerid` / `nickname` |
